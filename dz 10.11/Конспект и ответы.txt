Прикладные протоколы. HTTP, SMTP и FTP

КОНСПЕКТ

Прикладной уровень задаёт смысл передаваемых данных. В учебном NetLab клиент посылает PING и ожидает PONG. TCP отвечает за доставку байтов по порядку, IP — за их адресацию и маршрутизацию. Правила NetLab определяют, как программа понимает полученные байты.

HTTP организует обмен по схеме «запрос — ответ». В адресе http://127.0.0.1:3040/api/events?limit=5 схема http задаёт протокол, 127.0.0.1 указывает на этот же компьютер, 3040 — порт сервера, /api/events — путь, а limit=5 — параметр запроса. Значение параметра интерпретирует приложение.

В HTTP/1.1 первая строка запроса содержит метод, путь с параметрами и версию протокола. Например, GET /api/status HTTP/1.1 запрашивает статус службы. Далее следуют заголовки, пустая строка и, если требуется, тело. Ответ начинается со строки состояния, например HTTP/1.1 200 OK. За ней также идут заголовки, пустая строка и возможное тело. Строки заголовков завершаются парой символов CRLF.

GET читает ресурс, HEAD получает заголовки без тела ответа, POST передаёт данные на обработку. PUT создаёт или полностью заменяет ресурс по указанному адресу, PATCH вносит частичные изменения, DELETE запрашивает удаление. GET и HEAD считаются безопасными: клиент запрашивает чтение. PUT и DELETE идемпотентны: при повторении запроса его предполагаемый эффект сохраняется.

Заголовок Accept сообщает, какой формат клиент готов принять. Content-Type описывает формат отправленного тела. Например, application/json означает JSON, а text/plain; charset=utf-8 — обычный текст в UTF-8. Content-Length указывает размер тела в байтах.

Коды 2xx обозначают успех, 4xx — проблему с запросом клиента, 5xx — ошибку на стороне сервера. Например, при успешном удалении возможен 204 без тела, при неподдерживаемом методе — 405, при слишком большом теле — 413, при неподдерживаемом типе данных — 415. Внутренняя ошибка имеет код 500, временная недоступность сервиса — 503.

HTTP не требует хранить историю обмена для интерпретации следующего запроса. Приложение при этом может хранить события и узнавать пользователя по токену или cookie. Несколько запросов HTTP/1.1 могут пройти по одному TCP-соединению. HTTP/2 позволяет вести несколько обменов одновременно в одном соединении, а HTTP/3 использует QUIC поверх UDP. HTTPS защищает обмен с помощью TLS.

SMTP передаёт письма. Отправитель приветствует сервер командой EHLO, указывает адрес отправителя (MAIL FROM) и получателя (RCPT TO), передаёт письмо после DATA и завершает сеанс командой QUIT. Для доступа к полученным письмам применяют IMAP или POP3.

FTP передаёт файлы и позволяет работать с каталогами. Команды идут по управляющему соединению, а содержимое файла или список каталога — по отдельному соединению данных. Обычный FTP передаёт данные и пароль открыто. FTPS защищает FTP с помощью TLS. SFTP выполняет файловые операции поверх SSH.

ОТВЕТЫ НА ВОПРОСЫ ДЛЯ САМОПРОВЕРКИ

1. Что определяет прикладной протокол?
Формат, смысл и порядок сообщений, допустимые команды и ответы на них. Например, в NetLab команда PING вызывает ответ PONG.

2. Чем HTTP-запрос отличается от TCP-соединения?
TCP-соединение предоставляет двусторонний поток байтов. HTTP-запрос — отдельное сообщение клиента в этом потоке. Браузер может запросить страницу, а затем иконку по тому же соединению.

3. Какие части есть у HTTP/1.1-запроса?
Стартовая строка с методом, целью запроса и версией HTTP, заголовки, пустая строка и необязательное тело.

4. Что означают GET и POST?
GET запрашивает представление ресурса. POST передаёт данные ресурсу на обработку. В практике GET /api/events читает список, а POST /api/events добавляет событие.

5. Для чего служит Content-Type?
Он сообщает получателю тип содержимого тела запроса или ответа. Например, по application/json сервер понимает, что тело следует разобрать как JSON.

6. В чём разница между 200, 201, 400 и 404?
200 OK — запрос выполнен успешно. 201 Created — создан ресурс, например новое событие. 400 Bad Request — запрос некорректен, например нарушен синтаксис JSON. 404 Not Found — запрошенный ресурс не найден.

7. Почему 404 не означает отсутствие сетевого подключения?
Клиент получил HTTP-ответ со статусом 404, то есть обмен с ответившим сервером состоялся. При отказе в TCP-подключении клиент получит сетевую ошибку ещё до получения HTTP-статуса.

8. Что означает идемпотентность?
Несколько одинаковых запросов оказывают тот же предполагаемый эффект, что и один. Например, после повторного DELETE ресурс остаётся удалённым, хотя код второго ответа может отличаться. Повторный POST в нашей практике добавит ещё одно событие.

9. Почему SMTP не предназначен прежде всего для чтения почты?
Его команды обслуживают отправку и пересылку письма. Чтение содержимого почтового ящика и синхронизацию папок обеспечивает, например, IMAP.

10. Чем FTP отличается от SFTP?
FTP использует управляющее соединение и отдельное соединение данных. В обычном FTP шифрования нет. SFTP — самостоятельный протокол для работы с файлами через защищённое SSH-соединение.
